## JWT authentication

- 3 minute mini exercise
    - Watch https://www.youtube.com/watch?v=UBUNrFtufWo

- Let's talk about token based authentication with JWTs
    - JSON Web Tokens

- A JWT has three parts and looks like `AAAA.BBBB.CCCC`
    - AAAA = Header part
    - BBBB = Payload part
    - CCCC = Signature part

- The header describes the JWT, for example what hashing algorithm is used
- The payload contains data that's carried inside, anyone can read this data
- The signature is a "hash" of the header and payload
    - Think of it as a "fingerprint" of the header and payload
    - This is made from the **payload and a secret value** stored in the server
    - This is made using the algorithm defined in the header
    - The purpose of the signature is security
        - It can verify that the JWT was created by the server
        - It can verify that the JWT was not edited by anyone

- Anyone can read the payload part
- Nobody can change the payload part

## Wrap-up

- JSON Web Tokens
- Created on the server during login
- Browser sends the token along with requests
- Unlike cookies, JWTs are not *automatically* sent by the browser
- Server checks it to verify where requests come from
- Can be stored in localstorage, but that is not secure
